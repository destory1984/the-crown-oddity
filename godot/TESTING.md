# 시험과 일꾼 운용 규칙

이 문서는 The Crown Oddity를 시험하고 고치는 모든 에이전트(Claude 본 세션, Claude 일꾼, 클라우드 세션, Codex 시험 놀이꾼)가 똑같이 따른다.
2026-10-25 하루 동안 GPT 손 시험 4바퀴(6 → 9)와 고침 판 v0.0.49 → v0.0.60을 돌리며 정한 것이다.

## 1. 어디서 돌리나

- 사용자 PC에서는 시험을 돌리지 않는다. 사용자가 2026-10-25 13:03에 "테스터는 이제 내 PC에서 내리자"라고 했다.
  - GPT 시험 놀이꾼(Codex), 고도 편집기, Open Godot MCP 서버를 PC에서 띄우지 않는다.
  - 화면 없이 도는 자동 시험과 내보내기(`dev.py check`, `test`, `build`, `ship`)는 PC에서 해도 된다(사용자, 2026-10-25 13:20). 막은 것은 GPT 시험 놀이꾼뿐이다.
- 시험은 클라우드에서 돌린다. 개발 저장소는 비공개 `destory1984/crown-oddity-dev` 다.
  - 클라우드 세션은 리눅스 고도로 `python tools/dev.py check` 와 `python tools/dev.py test` 를 화면 없이 돌린다. 설치 방법은 `CLAUDE.md` 의 "클라우드(리눅스)에서 시험하기"에 적는다.
  - 클라우드 세션은 끝나도 본 세션에 알리지 않는다. 결과는 마지막 메시지와 브랜치로 남기고, 본 세션은 깃허브에서 브랜치를 확인한다.

## 2. 시험 바퀴 (시험 → 고침 → 다음 시험)

- 한 바퀴의 보고를 고쳐 판을 하나 낸 다음, 그 판으로 다음 바퀴를 돌린다. 고치기 전에 다음 바퀴를 미리 돌리지 않는다.
- 다음 바퀴는 먼저 지난 바퀴에서 고친 것을 같은 방법으로 다시 보고 "고쳐짐 / 안 고쳐짐"을 숫자로 적는다. 그다음 새 구간을 진행한다.
- 보고서는 `shots/playtest/reportN_*.md` 에 쓴다. 40줄 이하, 무거운 것부터 번호 목록으로 쓰고, 항목마다 곳, 단계, 기대, 관찰을 적는다. 이야기체와 "잘 된 것" 목록은 쓰지 않는다.
- 손 시험은 사람처럼 키를 눌러 한다. 상태 바꾸기(eval)는 시작 장면을 차릴 때 한 번만 쓰고, 그 뒤에는 읽기만 한다. 싸움을 이기거나 단계를 건너뛰는 데 쓰지 않는다.
- 싸움 시험은 곳마다 40 → 60초 동안 공격, 구르기, 달리며 공격, 기술을 섞고 0.1 → 0.3초마다 방향을 바꾼다. 입력 묶음마다 위치를 읽어, 구르기나 돌진 없이 1칸 넘게 움직이면 적는다.
- 화면 찍기는 한 바퀴에 12장 이하, 폭 800px로 찍는다.
- 일꾼이 고도를 쓰는 동안에는 시험 놀이꾼을 돌리지 않는다. `dev.py` 는 시작할 때 모든 고도 창을 닫으므로 서로 엉킨다. 일이 끝난 일꾼이 기다리는 상태로 남아 있으면 먼저 멈춘다.

## 3. 소리

- 시험할 때는 소리를 내지 않는다(사용자 요청, 2026-10-25).
  - `dev.py shot` 은 고도를 `--audio-driver Dummy` 로 띄운다. `check`, `test`, `build` 는 화면 없이 돌아 소리가 없다.
  - MCP로 게임을 띄우면 맨 먼저 `godot_exec eval` 로 `AudioServer.set_bus_mute(0, true)` 를 부른다.

## 4. Open Godot MCP (손 시험 도구)

- 0.1.10을 `addons/open_godot_mcp` 에 넣었다. 다리는 고도 편집기가 이 프로젝트를 열고 있을 때 `ws://127.0.0.1:6970` 에서만 열린다. 내보낸 판에서는 `export_presets.cfg` 의 exclude_filter로 애드온을 뺀다.
- 부르는 모양은 `{"action": ..., "params": {...}}` 다. 예: `godot_exec eval` 의 `params.code` 에 `var m = get_tree().current_scene` 을 쓰고, `godot_input key` 에 `{key, pressed}` 를 넣는다.
- Codex로 돌릴 때는 `bash tools/gpt_lap.sh 주문.md 기록.txt` 를 쓴다. 도구마다 승인을 미리 열어 두지 않으면 Codex가 "approval policy is never"로 모든 호출을 거절한다.
- Agnes, NVIDIA 도구는 켜지 않는다. 그림을 공개 파일 서버(uguu.se)로 올린다.

## 5. 일꾼 (고치는 에이전트)

- 지시서는 `shots/plans/이름_plan.md` 에 쓰고, 일꾼에게는 그 파일과 `CLAUDE.md` 의 파일 지도만 준다. 일꾼은 필요한 `sys/*.gd` 파일만 읽는다.
- 지시서대로 고치는 일은 가벼운 모델(sonnet)에 맡긴다. 큰 기능, 구조 바꾸기, 어려운 버그는 큰 모델(opus)에 맡긴다.
- 기능 하나가 판 하나다. `python tools/dev.py ship -m "영어 요약"` 이 판 번호를 하나 올린다.
- 판마다 게임 속 "바뀐 것"과 `rpg_demo/CHANGES.md` 에 같은 내용을 적는다. 맨 앞에 제목 문장을 쓰고, 아래 줄마다 "다"로 끝나는 짧은 문장 하나를 쓴다. 틸드는 쓰지 않고 바뀜은 → 로 적는다.
- 확인은 숫자가 먼저다. 자동 시험의 단언과 MCP 읽기로 확인하고, 눈으로 봐야 하는 바뀜만 화면을 한 장 찍어 본다.
- 전체 시험이 모두 통과해야 내보낸다. 가끔만 실패하는 시험은 그냥 두지 말고, 같은 판에서 원인을 찾아 고정한다.
- 내보낸 뒤 남은 생성 파일(`.uid`, `i18n/text.ko.translation`)도 커밋해 작업 폴더를 깨끗하게 둔다.

## 6. 커밋과 올리기

- 커밋 작성자는 `13573570+destory1984@users.noreply.github.com` 만 쓴다.
- 일꾼과 시험 놀이꾼은 올리지(push) 않는다. 올리기는 본 세션이 한다.
- 깃허브에는 계정 전체를 통틀어 1시간에 한 번만 올린다(2026-10-8에 계정이 잠긴 적이 있다). 두 저장소를 올릴 때는 한꺼번에 올린다.
- 올리기 전에 올라갈 차이에 지메일 주소, 개인 경로(`C:/Users/...`), 비밀값이 없는지 본다. `.codex/` 처럼 로컬 경로가 든 설정 폴더는 `.gitignore` 에 넣는다.
